# 按实际效果微调：条件、预算与证据

适用于从模板生成或修改工作汇报、Paper Reading。默认逐项继承源格式；本节允许必要的局部微调，不授权重新设计主题。用户的具体要求仍优先，独立科研绘图走其专用指引。

## 什么情况下才能调整

先填入真实内容并渲染。只有能够在具体页面、对象上指出以下问题，才进入微调：

| 可见问题 | 优先采取的措施 |
| --- | --- |
| 裁切、溢出、遮挡、过密导致难读 | 精简重复文案、调整内容区域和图文分配；其次调整段距/行距/字号 |
| 标题与所属说明分组不清、段间距明显失衡 | 调整局部位置或段前/后，保留段落层级与阅读顺序 |
| 缺字、错误字形、不可接受的字体替代 | 先检查字体环境和原字体可用性；确实无法正确渲染时才替换受影响的文字字体 |
| 实际背景上的文字对比不足 | 在模板现有配色中选择清晰的同角色颜色；先排除图片或背景放置不当 |

“更美观”“更专业”“我习惯用这个字体”“想统一一下”不能单独构成触发原因。内容少、留白多本身也不构成缺陷。环境预览缺字体不代表用户文件的字体有错；优先换用支持原字体的渲染环境。

已有 PPT 的局部修改仍受用户指定范围约束，不能顺手修整其他页面。先考虑对内容和布局影响更小的办法；不要求机械试遍所有办法，但须说明低影响办法为何不足或不适合。

## 可以改什么、最多改多少

以下数值是**本 skill 的保守默认微调预算**，不是通用排版标准，也不是鼓励用满的目标。始终相对原始映射源计算，不能通过连续小改、更换基准或轮流改段前/段后累积突破。

| 属性 | 局部调整范围 | 仍须保持 |
| --- | --- | --- |
| 内容区位置、文本框外部边界、图文分配 | 在内容区内改善问题，不覆盖导航、装饰或其他内容 | 画布、模板来源、可编辑性、阅读顺序；不得缩放整组文字来绕过字号预算 |
| 段前/段后 | 每段 `abs(新段前−源段前) + abs(新段后−源段后) ≤ 6 pt`，且新值非负；相邻两段之间的“前段段后＋后段段前”相对源之和变化也 ≤ 6 pt | 段落层级、项目符号、缩进、对齐、制表位；不能用空段落/空格模拟间距 |
| 行距 | 相对源值变化 ≤ 10%，保持原单位；倍数行距不得低于单倍 | 不将倍数偷偷改成固定值；固定行距还须实际检查无字形裁切 |
| 字号 | 每处相对源值变化同时满足 **≤ 2 pt 且 ≤ 10%** | 标题/正文/辅助文字的主次与投影可读性；禁止自动缩字、横向压缩、全页统一字号 |
| 字体 | 仅为已验证的缺字或字体替代问题更换受影响字体，选字形覆盖完整、风格和宽度接近的字体 | 中文/西文/符号角色、字号层级；不得把标题、正文和 Wingdings 符号一起替换 |
| 字体颜色 | 仅修复实际低对比，从源模板已有的同类颜色值或主题色中选择 | 语义角色和主题色引用方式；不新增配色、不改主题色定义、不凭喜好换强调色 |

不在预算内开放母版、版式、主题、项目符号体系、全局字体归一、字符压缩和文本框自动适配策略。若用户明确要求重设计则按其指定范围另行处理，不能把它伪装成“微调”。

同角色保持一致的视觉规则，但局部缺陷不授权全文件批量修改。若多页确有同类问题，可以复用同一微调规则，仍须逐项定位并检查每个受影响页面。需要较大改动时，先换页型、重分内容或拆页；与用户固定内容/页数确实冲突时说明冲突，不自行扩大预算。

## 实际执行顺序

1. **保留基准**：记录源页、源对象和源段落。填入真实内容，保留默认格式，渲染问题页；“调整前”必须是本次真实内容的页面，不能用空白模板截图代替。
2. **定位与选择**：记录可见问题，优先处理内容与布局，再考虑段距、行距、字号；字体和颜色只适用上面的专门条件。一次仅改变解释该问题所需的最少属性，不能顺手整套换样式。
3. **逐项登记后修改**：记录输出页/shape/段号/属性、原值→新值、具体原因、其他方案为何不适合，以及前后渲染路径。布局改动可写工作笔记；受检文字属性必须同时写入格式映射的 `adjustments`，见下节。
4. **检查结果**：用相同内容、渲染器与显示尺度比较调整前后，确认问题得到改善，且没有新增裁切、遮挡、难读文字或层级混乱；检查相邻对象和同角色文字。无改善或带来更大问题就回退。
5. **校验最终文件**：针对原始源运行格式检查。未登记的变化仍失败；登记项也必须匹配实际值并满足预算。所有受影响页都须从最终 PPTX 重新渲染，不能复用旧截图。合规微调不必逐次询问用户。

变更记录是内部工作材料，不加入展示页；同类问题的说明和渲染图可以复用，属性定位仍须准确。机器只能检查变更范围与预算，不能证明问题真实存在或修改后更好，必须实际查看前后图。

## 校验器中的逐项登记

在 `template-map.json` 顶层加入可选 `adjustments` 数组。下例只展示一项调整，其他映射字段照旧保留：

```json
{
  "adjustments": [
    {
      "slide": 1,
      "shape": "5",
      "paragraph": 1,
      "path": "a:pPr/a:spcAft/a:spcPts",
      "attribute": "val",
      "before": "0",
      "after": "400",
      "issue": "grouping",
      "reason": "真实内容渲染中，一级标题与后续说明贴得过近，分组不清",
      "alternatives": "缩短文字无法改变两段距离；分开文本框会破坏连续段落结构",
      "before_render": "qa/slide-1-before.png",
      "after_render": "qa/slide-1-final.png"
    }
  ]
}
```

`slide`、`shape`、`paragraph` 均定位**输出文件**，页和段从 1 开始。`path` 相对于映射源段落及输出段落的 `a:p`，不含 `a:p` 自身；`before`/`after` 是精确 XML 属性字符串。例如 `400` 表示 4 pt，字号 `2400` 表示 24 pt，行距百分比 `100000` 表示单倍。

允许的精确节点路径如下，不接受通配符、整段忽略或修改基准：

| 属性 | `path` | `attribute` | `issue` |
| --- | --- | --- | --- |
| 段前/后 | `a:pPr/a:spcBef/a:spcPts` 或 `a:pPr/a:spcAft/a:spcPts` | `val` | `overflow` / `overlap` / `grouping` / `spacing_imbalance` |
| 行距 | `a:pPr/a:lnSpc/a:spcPct` 或 `a:pPr/a:lnSpc/a:spcPts` | `val` | 同上 |
| 字号 | 字符属性路径 | `sz` | 同上 |
| 字体 | 字符属性路径后接 `/a:latin`、`/a:ea` 或 `/a:cs` | `typeface` | `missing_glyph` / `font_substitution` |
| 颜色 | 字符属性路径后接 `/a:solidFill/a:srgbClr` 或 `/a:solidFill/a:schemeClr` | `val` | `low_contrast` |

字符属性路径为 `a:r[N]/a:rPr`、`a:fld[N]/a:rPr`、`a:pPr/a:defRPr` 或 `a:endParaRPr`；`N` 为明确的 1-based 序号。需要同步的段内默认格式、可见 run 和段尾格式应逐项登记，不能只改一处后用“视觉相同”忽略其他差异。

脚本目前仅支持**源与输出均有相应显式属性**且定位唯一的微调。包含登记项的段落须保留 run 的数量、类型与顺序，逐位置核对格式，防止未登记的修改藏在相邻同样式 run 中。缺省/继承值、换单位、增加颜色节点、同时重组被调整的 run 等情况不能靠猜值通过；需要补充继承解析和等价专项校验。原生公式、表格、图表等未覆盖结构仍按格式流程处理。脚本不验证渲染引用是否真实、原因是否成立，也不检查布局坐标或字号层级；这些属于必须完成的视觉验收。

纯继承通过显示 `PASS`；存在通过机械检查的登记微调时显示 `PASS_WITH_ADJUSTMENTS` 并列出接受项，均退出 `0`。这两个状态都不能替代视觉验收。不能把有微调的文件描述为“全部格式与源完全一致”；应描述为“沿用模板，完成经检查的局部微调”。
