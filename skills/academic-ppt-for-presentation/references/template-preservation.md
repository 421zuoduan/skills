# 保留格式的编辑与校验

工作汇报、Paper Reading 及已有汇报 PPT 的编辑必读。独立科研绘图按 `ppt-drawing.md`。以下路径以本 skill 目录为基准，运行时解析成真实路径；不要依赖当前工作目录。

## 1. 确定唯一格式基准

- 新建汇报：`assets/reference.pptx`。用户明确指定其他模板时用指定文件；只作为内容来源提供的论文或 PPT 不自动成为视觉模板。
- 局部编辑：用户最新保存的 PPTX，先保留只读副本。按原范围修改，不把用户已做的调整统一回内置模板。
- 默认继承源格式；符合 [有边界的微调规则](controlled-adjustments.md) 的局部变化可逐项登记，不改变基准。超出该规则的变更仅在用户明确要求时适用。若用户已要求换字体等具体变更，先在独立基准副本中只落实这些已授权属性并记录要求与差异，再以该副本校验后续内容编辑。不得事后用输出文件作为基准、修改基准来消除失败，或把“优化/美化”当作任意改变格式的授权。内置资产始终不改。

查看模板预览并渲染实际要用的源页，检查角色、布局与继承；内置 `preview.png` 只显示封面，不能代表全部页型。选择适合内容的源页后记录映射，先复制/排列页，再填内容。

## 2. 复用对象与段落

**推荐做法：复制源幻灯片及其有效关系，在原生对象中替换文本。** 保留版式、母版、主题、媒体引用和包内关系；复制幻灯片必须正确更新演示页列表、关系及内容类型。仅 `add_slide(layout)` 会缺少样例页上的实际对象，不等于复制该页。使用成熟的复制方法，或核对完整 OOXML 关系。

| 操作 | 要求 |
| --- | --- |
| 替换已有文字 | 改已有 `a:t` 或已有 `run.text`，保留相邻格式节点。含多种样式的段落按原 run 角色分配新文字 |
| 新增正文段落/列表项 | 深拷贝同角色源 `a:p`，保留 `pPr`、`defRPr`、`rPr`、`endParaRPr`；替换文字并记录源段号 |
| 新增文本对象 | 复制同语义角色的源对象，分配唯一 shape ID，保留 `bodyPr`、`lstStyle`、占位符和字体引用；记录源对象 |
| 改页数与内容 | 可增删、重排源页，删除无用样例对象；选择合适源页型，保持模板装饰与继承 |
| 处理溢出 | 先改文案、内容分配或页型；必要时按 [有限微调规则](controlled-adjustments.md) 调整指定段落/文字属性，记录前后值并验证 |

禁止使用以下捷径：

- `shape.text = ...`、`text_frame.text = ...`、`paragraph.text = ...` 或 `clear()` 后重建文本，会删除原段落/run 或丢失字符格式。只有低层原位替换或确实保留全部属性的方法可用。
- 空白 `Presentation()` / `new pptxgen()` 后按截图和配色重画；导入模板后删掉原文字框，再用 `addText()` 重建。
- `fit_text()`、自动缩字、全局 font/size/color setter，以及未登记的段前/后、行距、字号等变化。有限微调只能改所登记的具体属性，不能整段/整框跳过比较。对齐、缩进、边距等未开放属性仍严格保留。
- 在模板里缺失的属性上写库的默认值；更改母版、版式或主题以修补单页。格式若已损坏，从基准还原对应节点。

直接编辑 XML 时用能保持命名空间声明的工具（如 `lxml`）；尤其保留 `mc:Ignorable` 所依赖的前缀。不要用可能重写/丢失前缀声明的简单 XML 写回方法。随附校验脚本中的标准库解析只用于只读检查，不是写回范例。

## 3. 建立格式来源映射

先对基准运行：

```bash
python3 "$SKILL_DIR/scripts/template_guard.py" inventory "$TEMPLATE" > "$WORK_DIR/template-inventory.json"
```

其中 `SKILL_DIR` 是本 skill 的实际绝对路径，`TEMPLATE` 是上述只读格式基准，`WORK_DIR` 是任务工作目录。输出包含模板 SHA-256、实际演示页序、shape ID、文字摘录和段号，也是一份原样复制全文件时可用的映射。制作时据此维护 `template-map.json`，不能对成品运行 inventory 来冒充源映射。

映射示意（只展示一个形状；实际须覆盖所有输出文本对象）：

```json
{
  "version": 1,
  "template_sha256": "inventory 生成的真实 SHA-256",
  "slides": [
    {
      "source_slide": 2,
      "shapes": {
        "5": {"paragraphs": [1, 2, 2]},
        "101": {"source_slide": 2, "source_shape": "5", "paragraphs": [2]}
      }
    }
  ]
}
```

- `slides` 数组顺序对应输出演示页序。源页号和段号均从 **1** 开始，页号不是压缩包里的 `slideN.xml` 文件编号。
- 每页 `source_slide` 指定所复用源页；`shapes` 的 key 是输出 shape ID，每个带 `txBody` 的对象（含空文本）都必须列出。
- 默认同源页、同 shape ID。新增/复制对象可用 `source_slide` 与 `source_shape` 指定来源；不能只因颜色相同就把正文映射到另一种语义角色。
- `paragraphs` 按输出对象的段落顺序给出源对象段号，可重复、可省去不再需要的源段落。例如 `[1,2,2]` 表示一个一级段落加两个复制自同一二级源段的段落。空段落也计数。
- inventory 中 `name`、`text` 是帮助选源的提示，不参与格式比较。基准 hash 用于防止拿错文件，不能手改来掩盖源文件变化。
- 需要有边界的微调时，在顶层加入 `adjustments` 数组，逐项给出输出定位、精确 XML 旧/新值、可见问题、替代方案与前后渲染引用。格式和预算见 [微调登记规范](controlled-adjustments.md)。没有登记时保持原有严格比较。

## 4. 最终文件必须检查格式，再检查画面

```bash
python3 "$SKILL_DIR/scripts/template_guard.py" check \
  "$TEMPLATE" "$OUTPUT_PPTX" --map "$WORK_DIR/template-map.json"
```

脚本只读，不修改文件。退出 `0` 表示其覆盖范围内通过：无微调时为 `PASS`，有通过机械检查的登记项时为 `PASS_WITH_ADJUSTMENTS`，并列出 `accepted_adjustments`。退出 `1` 表示格式不一致，`2` 表示输入/映射有误、变更记录不合法或存在不支持的结构。不得忽略退出码；修复源生成逻辑后重新导出并校验。任何通过状态都不能证明视觉更好。

检查的核心是**与映射源格式一致，只放行有边界且逐项登记的变化**，而非“全文件只许出现几种字号”：

- 画布尺寸、演示默认文本样式、每页的版式→母版→主题及相关颜色映射；防止表面 run 不变但继承来源被改。
- 每个原生文本对象的 `bodyPr`、`lstStyle`、字体引用和占位符语义。
- 每段完整 `pPr`、`endParaRPr` 与 run 格式序列，包括字体、字号、色值/主题色、粗斜体、字距、行距、段前/后、缩进、对齐和原生项目符号。允许重复相邻同格式 run；混合样式段落不能合并成单一样式。
- 所有输出页、文本对象及段落的映射完整性。不检查文字内容，也不要求内容和段落数量与模板相同。
- 有登记微调时，核验源值、实际新值、属性范围和预算；只在内存中的源段副本上应用这些精确变化后比较。未登记的节点仍严格比较，原始基准和文件不变。

该脚本是保守的 XML 格式一致性检查，视觉等价的样式重写也可能被拒绝；不是完整 PowerPoint 渲染器或文件结构验证器。表格、原生图表、SmartArt、原生公式等未覆盖的文字结构会报告不支持，不能作为通过；确需保留这些结构时补充等价的格式检查，不删除检查、不把整页转图片来绕过。新增内容资产的说明标签沿用模板辅助文字角色，不能据此解锁页面正文。图片、公式图的内部字形、文本框几何、装饰位置、实际字体替代、内容正确性和语义角色选择仍需人工/agent 对照，不能靠脚本作保证。

从**最终保存的 PPTX** 渲染每页，与映射源页并排核对字体、颜色、大小、项目符号、段落间距、导航和装饰。检查越界、裁切、遮挡及公式；确认文字仍可编辑。发生微调的页还要与同内容的调整前渲染对照，确认问题改善且没有新的问题。校验与视觉检查任一缺失，交付说明应准确写明未验证项；有微调时不能声称所有格式与源完全一致。

## 设计依据

- [Anthropic 的 PPTX skill](https://github.com/anthropics/skills/blob/main/skills/pptx/SKILL.md)：模板编辑路径、原对象复用、run 级文字替换及文件/视觉验收。本 skill 仅借鉴保留格式的机制，不采用其从零设计时的配色、字号或缩字建议。
- 本机会话提供的 Presentations `references/template_following.md`：检查真实参考、复用源结构、保留主题和间距、输出后对照。本 skill 自包含，不要求其他 coding agent 安装或加载该文件。
- [python-pptx 文本 API](https://python-pptx.readthedocs.io/en/latest/api/text.html) 与 [文本编辑说明](https://python-pptx.readthedocs.io/en/latest/user/text.html)：文本框/段落/run 的层级、整体赋值的替换行为、缺省属性的继承及 `fit_text()` 的字号修改。
